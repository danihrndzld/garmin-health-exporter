# GarminDownloader — Agent Instructions

This repo is managed with the **WAT framework** (Workflows, Agents, Tools). Probabilistic AI orchestrates; deterministic code executes. Keep the layers separate and the system stays reliable.

## WAT Layout

- [workflows/](workflows/) — markdown SOPs. Each one states objective, inputs, tools, outputs, and edge cases.
- [tools/](tools/): one Go program that does the actual work (tests, builds, releases, API probes). It is its own Go module (`tools/go.mod`, standard library plus `github.com/danihrndzld/gconnect`), separate from `tauri-app/core`, so the core's architecture rules do not apply to it. Run it from the repo root as `go run -C tools . <command> [flags]`. Relative paths in flags are read from the repo root. `go run` turns every non zero exit code into 1 and prints `exit status N`; N is the tool's real code. Tests: `cd tools && go vet ./... && go test ./...`.
- [.tmp/](.tmp/) — disposable intermediates. Gitignored. Regenerate freely.
- [.env](.env) — API keys and secrets. Gitignored. Never store secrets anywhere else.
- `credentials.json`, `token.json` — Google OAuth. Gitignored.

Everything the user needs to *see* lives in cloud services (Sheets, Slides, etc.) or in `tauri-app/dist/` for app builds. Local scratch files are processing-only.

## How to Operate

1. **Match the request to a workflow.** Read the workflow end-to-end before acting.
2. **Look for an existing tool first.** Scan `tools/` before writing anything new.
3. **Run tools, don't imitate them.** Probabilistic reasoning + deterministic execution is the whole point.
4. **On failure: diagnose, fix the tool, verify, then update the workflow** so the same error can't recur silently. If the fix costs paid API credits to retest, confirm with the user first.
5. **Never overwrite a workflow without permission.** Workflows are instructions — preserve and refine them.

## Available Tools

| Tool | Purpose | Invocation |
| ---- | ------- | ---------- |
| `ci` ([tools/ci.go](tools/ci.go)) | Full CI/CD for `tauri-app/` (clean → install → test → universal build in a worktree → open). Never prints the key or token. | `go run -C tools . probe [--end YYYY-MM-DD] [--days N]` |
| `test-report` ([tools/testreport.go](tools/testreport.go)) | Runs every suite (`ids`, `go`, `ui`, `e2e`, `cargo`) to the end with JUnit output (Go through the converter in [tools/junit.go](tools/junit.go)), Go coverage and the Playwright flaky count, then builds `report.html`/`report.pdf`/`summary.html` with the art-of-cicd skill's `build_report.py` through `python3` (`ART_OF_CICD` overrides its dir) into `tauri-app/reportes-pruebas/<date>-ci/`. | `release` ([tools/release.go](tools/release.go)) | End-to-end release: preflight → bump → build (runs `ci --no-open` in the same process) → verify DMG → FF merge into main → tag → one atomic push of the branches and the tag → `gh release create` with the universal DMG. Supports `--bump {patch,minor,major}` or `--version X.Y.Z`, `--source`, `--notes` / `--notes-file`, `--prerelease`, `--skip-merge`, `--dry-run`, `--rustup-home`, `--cargo-home`. | `go run -C tools . release --bump <kind> [flags]` |

## Project Context (non-WAT)

- `tauri-app/` is the Tauri 2 app (v4, 4.5.0 first build with one Go binary). Vanilla HTML/CSS/JS in `tauri-app/ui/` (no bundler); every command runs in the Go core `garmin-export-core` (below), a Tauri `externalBin`; Rust only does the MyFitnessPal sign in window. Protocol: one JSON request line on stdin (password never in argv), JSON lines out (`log` / `progress` / `result`). The binary is the trust boundary: range, refresh window and `$HOME` containment are validated there. `ui/date-range.js` is a tracked file. Dev: `cd tauri-app && bun install && bun run dev`; build: `bun run build` (host arch); release: `bun run release` (universal DMG, needs rustup targets aarch64 + x86_64-apple-darwin; Homebrew rust lacks x86_64, so v4.0.0 was built with an isolated rustup via RUSTUP_HOME/CARGO_HOME). `beforeBuildCommand` (`bun run core:universal`) builds the universal Go binary with `lipo`. Never `tauri build` in this checkout while the user runs the app from `src-tauri/target/release/bundle`; build in a `git worktree` instead (`go run -C tools . ci` does). v4 releases go through the release tool (`go run -C tools . release`; `tools/release.py` until 4.6.0) from 4.5.0 on. Preview the UI in a plain browser via `ui/dev-mock.js` (`python3 -m http.server -d tauri-app/ui`).
- Go core (`tauri-app/core`, binary `garmin-export-core`; specs `docs/superpowers/specs/2026-10-14-go-core-mfp-design.md`, `2026-10-16-go-core-garmin-design.md`, architecture `2026-10-16-architecture-hexagonal-gconnect.md`). Commands: `garmin-status` (never sends a request; the key under `apiKey`), `garmin-connect` (the only command that signs in; password on stdin only; with `apiKey` instead it trades a Personal API key for a token once and never signs in), `garmin-disconnect` (`which`: `login`, `apiKey`, or both when missing), `clear-cache`, `export` (Garmin; `garmin:false` only makes the `csv_*` dir), `mfp-export`, `summary`, `pack` and `report`. Packages: `internal/garmin`, `mfp`, `pack`, `report`, `guard`, `jsjson`, `protocol`, `atomicfile`; redaction comes from `gconnect` (`Redact`, `RedactURL`). The data dir holds `tokens.json` (0600, the shapes the old `auth.js` wrote plus `saved_at`), `garmin-api-key.json` (0600, gconnect `Tokens.Personal` plus `saved_at`; its own file so a dead key never replaces the login), `sso-cooldown.json`, `garmin-cache/daily/<date>.json` and `garmin-cache/activity/<id>.json`, `mfp_session.json` and `mfp-cache/`; Clear cache deletes `garmin_cache.db`, `garmin-cache/` and `mfp-cache/`, never the logins. A dead login (400/401 from the DI refresh grant, 401 from the legacy OAuth2 exchange, or a second 401 on data after a refresh) replaces `tokens.json` with the expired marker `{"expired_at","saved_at"}`, which holds no secret; a network error, 5xx, 403 or 429 keeps the tokens. `GARMIN_FAKE_SERVER` and `MFP_FAKE_SERVER` are read by Go, loopback URLs only, on every request. Goldens: `internal/garmin/testdata/golden` (rebuild only with `UPDATE_GOLDEN=1 go test ./internal/garmin -run AC301`), `internal/mfp/testdata/golden`, and the stage 3 goldens `internal/pack/testdata/golden`, `internal/report/testdata/golden.json` and `cases.json`, frozen from the JavaScript on 2026-10-16 and never regenerated (the JavaScript is gone). The Go binary never opens `garmin_cache.db` (old sql.js file; Clear cache still deletes it). Rust (`mfp_connect` / `mfp_disconnect` / `mfp_status`) writes `mfp_session.json`; Go only reads it and rewrites it on cookie rotation.
- Go layout and its strict rules (Hexagonal, enforced by `tauri-app/core/arch_test.go`, which `go test .` runs): `cmd/garmin-export-core` is the only place that reads the environment, stdin, stdout or args (the time zone name for the pack is resolved there) and the only importer of `internal/protocol`; no exported function or type of `internal/garmin`, `internal/mfp`, `internal/pack` or `internal/report` holds `map[string]any` (the wire shape belongs to `cmd/`); `internal/garmin` and `internal/mfp` never import each other; the Garmin sign in and API client is the public library `github.com/danihrndzld/gconnect` (repo `~/Developer/gconnect`, MIT, standard library only, never touches the disk; `go.mod` requires exactly that one module at a pinned tag, currently v0.2.1, and `arch_test.go` allows nothing else); its `gconnecttest` package is the fake Garmin every test uses. A library change is made in that repo, tagged, then taken with `go get github.com/danihrndzld/gconnect@vX.Y.Z && go mod tidy` (for local work on both, a gitignored `tauri-app/core/go.work`; never a `replace` in `go.mod`). The app adds its own wording for the MFA and rate limit messages in `internal/garmin`. `CGO_ENABLED=0`, universal binary through `lipo`. Every path in a request resolves inside `$HOME` through `guard.InsideHome` in `cmd/`; `pack` also needs an existing `csv_*` directory; `report` never touches the disk.
- Garmin Personal API key (gconnect v0.2.1+, `workflows/personal_api.md`): preferred. `internal/garmin/personal.go` asks the Personal API host for a few range requests (v2 daily summaries and HRV 90 days, sleep and Body Battery 31, steps 28) and maps them onto the legacy per-day shapes, so `csv.go` and its goldens never change. With the login saved too, the login asks only for the names the key did not fill (training, laps, goals, ...); with the key alone the export logs one `PERSONAL_API_LIMITS` warning. The Personal API answers 404 outside its documented paths and needs no display name, so `social_profile` is never asked with the key. A 400/401 on the token request marks only `garmin-api-key.json` expired (`GARMIN_SESSION` naming the key; with a live login the export runs on it and warns `GARMIN_KEY_EXPIRED`).
- Garmin login (`auth.go` of `github.com/danihrndzld/gconnect`, ported from the JavaScript at tag `archive/electron-app`): only `garmin-connect` signs in, at most twice (mobile, then widget); an export never signs in and ends with `GARMIN_SESSION` when the login is missing or dead. DI OAuth first (SSO `/mobile/api/login` -> `diauth.garmin.com` token, as python-garminconnect 0.3.x), the old garth widget + OAuth1 flow once as fallback. DI tokens need the native `X-Garmin-*` headers on connectapi (403 without them). A 429 on both logins writes `sso-cooldown.json` (15 min). Never run live login experiments in a loop: Garmin rate limits sign ins per account (429 after 4 logins in 40 minutes on 2026-10-14).
- Tests (trophy shape): `cd tauri-app && bun run test && (cd src-tauri && cargo test)`. `bun run test` runs `scripts/test-ids.js`, `go vet` and `go test` in `core`, `ui/__tests__` and Playwright; the Go tests run against the `gconnecttest` fake Garmin and the MFP fake. The fixture is scrubbed by `bun tauri-app/scripts/make-fixture.js` with a per-run secret; never commit raw export JSON. Compare two `csv_*` folders with `bun tauri-app/scripts/compare-csv.js <old> <new>`.
- UI e2e regression (`tauri-app/e2e`, Playwright, Chromium + WebKit): `cd tauri-app && bunx playwright test`. Black box through `ui/dev-mock.js` served by `e2e/support/serve-ui.js`. Page Object Model: one page object per component in `e2e/pages/`, mock switches only in `e2e/support/mock-backend.js` (it maps intent to the mock's `localStorage` keys), "today" pinned by `FixedToday`, wiring only in `e2e/fixtures.js`, assertions only in specs. Every test name starts with its technique ID (EP, BVA, ST, DT, EG, CL, AC); Go IDs: 101+ and 2xx to 3xx (stages 1 and 2), 601+ (stage 3), 701+ (Personal API key). Every ID is unique across `tauri-app` and sits in a test, `t.Run` or row name; `bun scripts/test-ids.js` checks it and runs in `bun run test`. Test reports go to `tauri-app/reportes-pruebas/` (gitignored); `go run -C tools . test-report` writes them, and CI uploads them as the `test-report` artifact.
- LLM pack (`tauri-app/core/internal/pack`, `units` is the `UNITS` table; test: `go test ./internal/pack`): the export writes no pack files; `BuildPreview` (pack.go) builds both languages in memory for the sheet. The sheet's buttons call the Go `pack` command, which writes ONE language into its own subfolder of the `csv_*` dir (`llm-<lang>/` = `CONTEXT.<lang>.md` + CSV copies, `llm-<lang>-one-file/` = context + all CSVs inline) and deletes v4.0.0's root-level pack files, so dragging a whole folder never duplicates data. Units are inferred from column-name suffixes in `UNITS`; check new columns there. The raw JSON is never packed (a 60-day export is ~38 MB, over Claude's 30 MB upload cap).
- The Electron 3.x app and the JavaScript core are at tag `archive/electron-app`; Go comments that name a `.js` file refer to that tag.

## Bottom Line

You sit between intent (workflows) and execution (tools). Read the SOP, call the right tool, recover from errors, and keep the framework sharper than you found it.
